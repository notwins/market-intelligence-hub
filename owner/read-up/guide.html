Publish a finished brief

  1. Save and preview the finished draft. Record actual article links, verification notes and citations. Use Our interpretation: and Our watch points: for those sections.
  2. Choose revision 1 for a new article bundle, or the next revision for an intentional correction. Click Prepare review bundle.
  3. Read the exact record and evidence in the local outbox. In this owner folder run: python approve.py --job JOB_ID --reviewer YOUR_NAME --approve. This attests facts, exact selection, privacy, rights and editorial quality. Do not approve until checked.
  4. Return here, tick the review confirmation and click Publish reviewed brief. Existing local Git authorization submits only the reviewed public record to the independent content repository.
  5. Refresh My drafts to see queued, committed, retry-needed, awaiting-live-verification or live-verified. A failure retains the original bundle and attempt history. If local Git access is unavailable, use the existing authorized publisher in this chat with the retained bundle; add no credentials.

The public subsection is on the Hub. Each finished brief has one card; old revisions keep their own URLs. No notes, drafts, source evidence or reviewer identity enters the public site. This desk is loopback-only and has no online owner sign-in.
