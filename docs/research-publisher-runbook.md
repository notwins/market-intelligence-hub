# Publish a complete report without editing the UI

Deployment destination changed on 14 November 2026: run this publication process
in `notwins/market-intelligence-content`, not the Hub UI repository. Read that
repository's README and `docs/independent-content-deployment.md` here. Its own
Pages workflow publishes new reports, feed and search without any UI release.
The Hub keeps existing articles and URLs. Do not migrate or reissue them.

## Channels

| Channel | Stable edition prefix | Publication rule |
| --- | --- | --- |
| `earnings` | `us-earnings-full` | New completed US earnings editions only |
| `credit` | `bond-credit-full` | New Global Markets & Credit Research editions only |
| `policy` | `central-banks-policy-full` | New completed Central Banks, Rates, FX & US Administration editions only |
| `standalone` | `standalone-<topic-slug>` | A substantive full report explicitly requested for public publication |

Source chat IDs and private input locations belong in private automation settings,
not the public record. Do not sweep private chats or folders for standalone work.
The source author's cutoff, rather than publication time, determines the dated ID.
Use the same topic slug for retries. A correction needs an explicitly reviewed
`--revision 2` or later; never use a new slug to evade a conflict.

The 14 November credit report already exists in the legacy register. It must not
gain a new card. The earnings pilot already exists in the automatic records.
Check the legacy register, current records, dated URLs and source cutoff before
preparing an edition. Different title wording alone does not make a new report.

## Prepare, review, publish

1. Finish the entire report in a private working area. Retain substantive sections,
   analysis, sources and limitations. Use the approved V3 contract/template at
   `site/colour-templates-v3/research-template.html.txt`. A PDF can be a companion;
   the complete HTML `index.html` remains required. Do not publish an extract as
   the full report. Verify material facts and publication rights; remove private
   client material and unlicensed datasets. Explain material exclusions.
2. Place only the intended public files in a flat `public-files/` folder. Save a
   private `metadata.json` containing exactly `title`, `cutoff_sgt`, `category`,
   `tags` and `summary`. Tags must exist in the current repository standard.
3. Run the shared preparation command, which validates the report, constructs
   the stable ID and hashes the actual public bytes:

   ```powershell
   python scripts/prepare_research_bundle.py --channel credit --report-dir <private-public-files> --metadata <private-metadata.json> --output <new-private-bundle>
   python scripts/prepare_research_bundle.py --channel standalone --slug <stable-topic> --report-dir <private-public-files> --metadata <private-metadata.json> --output <new-private-bundle>
   ```

   Use `--brief brief.html` or `--brief brief.pdf` only after reviewing it as the
   matching edition. Otherwise omit the option: the record has `quick_read:null`.
   No approval receipt is generated by this command.
4. After completeness, factual, rights, privacy, link and rendered accessibility
   review, issue the private receipt described in `research-release-separation.md`.
   Bind it to the returned canonical record hash. Keep it outside the bundle and
   repository. Never turn failed checks into true attestation fields.
5. Use `submit_research.py --remote <remote> --bundle <bundle> --review <receipt>
   --output <new-candidate>` to accept the edition on a disposable latest-main
   clone. Run `research_release_guard.py` with the full base and candidate SHAs.
   Only new `site/research/<id>/*` and `site/data/research-records/<id>.json` may
   be in the publication commit. Run the normal builders and final artifact
   validator. Do not include generated files in the submitted commit.
6. Publish using existing authorized GitHub tools with `expected_sha` and a tree
   based on the freshly inspected main, or the shared Git submit path. Never force.
   If main advanced, reaccept on its new tree and rerun the checks before retrying.
   Identical editions are no-ops; conflicting IDs are held for review.
7. Wait for Pages success and read back the live report hash, feed entry, actual
   cutoff, direct link and search entry. A commit or saved automation is not proof
   of successful publication. Record which checks were actually completed.

## Standalone report instruction

Use this in a future task only when the user requests public publication:

> Publish this completed standalone research report to Market Intelligence Hub
> using docs/research-publisher-runbook.md and the shared prepare/submit scripts
> from latest main. Preserve the complete report, dated sources and limitations;
> perform the public-safety and rights review. Use a stable topic slug, one dated
> immutable full-report destination and one record, with a matching brief only
> when verified. Do not edit UI files, hand-build a card, migrate older articles
> or expose private source material. Use the existing guarded GitHub publisher,
> run the final artifact checks and verify the actual live report/feed/search.

This instruction is reusable, not a new scheduled automation and not blanket
authorization to publish every private research draft.

## Hourly news stays separate

The Reuters news producer currently labels its source reports four-hourly. The
existing hourly publisher polls for newly completed reports at :15; polling does
not change the producer's cadence. Use `import_hourly_news.py` and `HOURLY_NEWS.md`,
not the full-report card lane. Keep source time/coverage and gaps truthful.
Preserve public story IDs and version chains; hold a follow-up if its predecessor
is not retained. Do not silently renumber it or invent historical versions. A
partial accepted edition may contain only independently verified eligible stories,
with held stories disclosed. Never claim that this fills the historical backlog.
New editions use the hashed private source identity and no private conversation URL.
Reconcile the feed on latest main on every retry; never overwrite it with a stale
whole-file copy. Existing archives remain immutable.

## Release limits

Article authors no longer edit the UI. Pages still deploys one combined artifact;
a broken main or failed shared build can block both lanes. Roll back only approved
UI-owned paths on current main and rebuild with current research. Never deploy an
old whole-site artifact. Fully independent serving needs a separately designed
hosting/routing boundary; no such service, routing change or old-content migration
is included in this rollout.
